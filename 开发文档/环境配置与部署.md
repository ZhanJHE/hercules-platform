# 环境配置与部署指南

> **适用工程**：`hercules-platform/`（阶段 A 多模块化之后，Boot 3.5.16 / Java 21）
> **部署模式**：
> - 模式一：本机直装（单进程 + 原生中间件），开发基线，日常开发与单进程调试用；
> - 模式二：WSL2 + Docker Compose（十容器栈），当前生效，用于阶段 H 压测与集成演示、阶段 B 真实 Binlog 同步链、阶段 G 前端（见第二节）。

---

## 一、本机直装模式（开发基线）

### 1.1 环境要求

| 组件 | 版本要求 | 本机现状 | 用途 |
| :--- | :--- | :--- | :--- |
| JDK | 21+（推荐 21/25 LTS） | JDK 25.0.3 已装 | 编译目标 `java.version=21`，向下兼容 |
| MySQL | 8.x | 已运行（3306，含 X 协议 33060） | 业务库 + `t_cache_version` 版本表 |
| Redis | 3.x+（基础命令兼容旧版） | 已运行（6379，无密码） | L2 分布式缓存 |
| Maven | 3.9.x | 无需安装（wrapper 3.9.16，首次运行联网下载） | 构建 |
| Docker | — | **不需要**（本机不可安装；扩展组件全部选 Windows 原生/嵌入式形态，见 §二） |

> 说明：应用对 Redis 仅使用 GET / SET(EX) / DEL 基础命令，Windows 原生 Redis build 或 Memurai 均可。

### 1.2 中间件安装（本机直装要点）

**MySQL 8**
1. 官方 Installer 安装 MySQL Server 8.x，设置 root 密码（本机当前为安装时自带服务，凭据见 `application-local.yml`）；
2. 确认服务为自启动：`services.msc` → MySQL80；
3. **无需手工建库**：连接串带 `createDatabaseIfNotExist=true`，应用首次启动自动创建 `hercules` 库并执行初始化脚本。

**Redis**
1. Windows 可用社区维护版（如 tporadowski/redis 的 release）或 Memurai，解压即用；
2. 默认端口 6379、无密码；若设置 `requirepass`，需同步修改 `application-local.yml` 的 `spring.data.redis.password`；
3. 验证：`redis-cli ping` 返回 `PONG`。

### 1.3 应用配置

配置文件位于 `hercules-platform/hercules-application/src/main/resources/`，分两层：

| 文件 | 作用 | 是否入库 |
| :--- | :--- | :--- |
| `application.yml` | 通用配置（端口、profile 激活、mybatis-plus、hercules.* 参数） | 提交 |
| `application-local.yml` | 本机凭据（数据库/Redis 连接） | gitignore，勿提交 |
| `src/test/resources/application-test.yml` | 测试环境（H2 内存库 + 桩 L2，不依赖本机中间件） | 提交 |

`application-local.yml` 模板（按本机实际修改密码/端口）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/hercules?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: root
    password: "你的密码"
    driver-class-name: com.mysql.cj.jdbc.Driver
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      # password: 无密码时省略

# JWT 签名密钥（≥32 字节随机串；生产环境必须更换且勿提交）
hercules:
  auth:
    secret: "这里放一段至少 32 字节的随机字符串"
```

**演示账号**（由 `AuthUserSeeder` 启动时幂等播种，BCrypt 密文现场生成）：

| 登录名 | 密码 | 角色 | studentId |
| :--- | :--- | :--- | :--- |
| admin | admin123 | ADMIN | — |
| st001 | 123456 | STUDENT | 20240001 |
| st002 | 123456 | STUDENT | 20240002 |
| st003 | 123456 | STUDENT | 20240003 |

**鉴权白名单**：`/api/v1/auth/login`、`/api/v1/auth/refresh`、`/actuator/health`、`/actuator/prometheus`；其余接口需 `Authorization: Bearer <accessToken>`；`/api/v1/enrollment/**` 仅 STUDENT，`/api/v1/cache/stats`、`/api/v1/debug/**` 仅 ADMIN。

`hercules.*` 业务参数（含默认值，见 `application.yml`）：

| 键 | 默认值 | 含义 |
| :--- | :--- | :--- |
| `hercules.sync.node-id` | `node-1` | 本节点向量时钟分量名（多实例演练冲突时设不同值） |
| `hercules.sync.max-nodes` | `10` | 向量时钟最大节点数告警阈值（风险 R-03） |
| `hercules.cache.local-ttl` | `60s` | Caffeine L1 详情键 TTL |
| `hercules.cache.remote-ttl` | `300s` | Redis L2 详情键 TTL |
| `hercules.cache.list-ttl` | `10s` | 列表键 TTL（最终一致窗口，L1/L2 均生效） |
| `hercules.cache.local-max-size` | `1000` | L1 容量上限 |
| `hercules.cache.circuit-breaker.enabled` | `true` | Redis 熔断装饰器开关（阶段 A+，故障时读直连 DB） |
| `hercules.cache.load-lock.enabled` | `true` | 分布式回源锁开关（阶段 A+，防缓存击穿；Redis 不可用自动跳过） |
| `hercules.cache.load-lock.ttl` | `3s` | 回源锁自动过期时长（防持有者宕机死锁） |
| `hercules.cache.load-lock.poll-interval` | `50ms` | 未抢到锁时探测 L2 的间隔 |
| `hercules.cache.load-lock.poll-budget` | `2s` | 未抢到锁时等待队长的总预算，超时走安全阀自行回源 |
| `hercules.sync.transport` | `in-process` | 同步链传输（阶段 B 增加rocketmq 选项） |

全链路超时（阶段 A+ 同步写入 `application.yml`）：Redis 命令 200ms / 建连 500ms、HikariCP 获取连接 3s（池上限 20）、SQL 语句 3s、选课事务 5s——最坏路径延迟有界，Redis 挂起不会拖垮 Tomcat 线程池。

### 1.4 构建与运行

```powershell
cd hercules-platform

# ① 全量测试（H2 + 内存桩，不依赖本机 MySQL/Redis，约 25s，应 113/113 通过）
.\mvnw.cmd test

# ② 打包（可执行 jar 约 47MB）
.\mvnw.cmd package -DskipTests

# ③ 运行（二选一）
java -jar hercules-application\target\hercules-application-0.0.1-SNAPSHOT.jar
.\mvnw.cmd spring-boot:run -pl hercules-application
```

- `mvnw.cmd` 依赖 PATH 中的 **Windows PowerShell**（Maven Wrapper `only-script` 模式的固有行为：wrapper 用它定位/下载 Maven）。
  若环境里 `powershell` 不可解析（例如只装了 PowerShell 7 而 PATH 未含 5.1），`mvnw.cmd` 会直接报
  `'powershell' 不是内部或外部命令`——此时改用本机 Maven 直接执行：`mvn -f pom.xml test`，
  或调用 `%USERPROFILE%\.m2\wrapper\dists\apache-maven-3.9.16\*\bin\mvn.cmd`（wrapper 已下载的发行版）；
- 默认端口 **8080**；启动即自动执行 `schema.sql` / `data.sql`（`CREATE TABLE IF NOT EXISTS` + `INSERT IGNORE`，**幂等**，可反复重启）；
- 就绪判据：`GET http://127.0.0.1:8080/actuator/health` 返回 `{"status":"UP"}`；
- 关注日志前缀：`[hercules-cache]`（缓存失效）、`[hercules-sync]`（版本应用/冲突合并）。

### 1.6 数据重置

- 应用数据全部在 `hercules` 库：`DROP DATABASE hercules;` 后重启应用即自动重建并重新播种；
- 冒烟会在 `t_enrollment`（status=2 退选记录）与 `t_cache_version` 留下演示残留，属预期，不影响功能。

### 1.7 常见问题排查

| 现象 | 排查 |
| :--- | :--- |
| 启动报 `Communications link failure` | MySQL 服务未启动（`services.msc`）或端口不符 |
| `Access denied for user 'root'` | 凭据与 `application-local.yml` 不符；确认密码后重试 |
| Redis `Connection refused` | redis-server 未启动；或设置了密码但配置未同步 |
| 首次构建依赖下载失败 | **网络问题：按约定停下报告，不盲目重试**；必要时配置 Maven 镜像（`~/.m2/settings.xml`，如阿里云镜像）后再试 |
| 端口被占（8080） | `netstat -ano | findstr :8080` 找 PID 结束进程，或改 `server.port` |
| 控制台中文乱码 | PowerShell 先执行 `chcp 65001`（UTF-8 代码页） |
| 多 JDK 干扰 | 设 `JAVA_HOME` 指向 JDK 21+；`java -version` 核对 |
| `mvnw.cmd` 报 `'powershell' 不是内部或外部命令` | Wrapper 需要 Windows PowerShell；改用 `mvn -f pom.xml test` 或直接调用 `.m2\wrapper\dists` 下的 Maven（见 §1.4） |

### 1.8 存量库升级：补建选课唯一键（一次性）

新建库由 `schema.sql` 直接建出 `t_enrollment.uk_student_course`（`(student_id, course_id)` 唯一）。
**存量库**（本机库或容器卷，创建于该约束加入之前）不含此唯一键，会允许同一学生重复选同一门课，
无效记录持续堆积——阶段 H-4 压测期间曾因此产生 51 万行记录，把 `/enrollment/mine` 与对话链拖垮。
升级时需手动执行一次（应用启动后执行即可，无需停服；执行前先备份 `t_enrollment`）：

```sql
-- ① 去重：同一 (student_id, course_id) 只保留 id 最小的一行
DELETE t1 FROM t_enrollment t1
JOIN t_enrollment t2
  ON t1.student_id = t2.student_id
 AND t1.course_id  = t2.course_id
 AND t1.id > t2.id;

-- ② 补唯一键（缺此键则重复选课不会被数据库拦住）
ALTER TABLE t_enrollment ADD UNIQUE KEY uk_student_course (student_id, course_id);

-- ③ 按有效记录校准 t_course.enrolled（status=2 为退选记录，不计入）
UPDATE t_course c
SET c.enrolled = (SELECT COUNT(*) FROM t_enrollment e
                  WHERE e.course_id = c.id AND e.status <> 2);
```

> 注：`schema.sql` 头部对该 ALTER 亦有注记；此处给出可直接复制执行的完整三步。

## 二、WSL2 + Docker Compose 部署（当前生效，阶段 H 起为压测和演示的标准形态）

> 前期曾因本机装不上 Docker Desktop 转向"多进程原生部署"（嵌入式 + Windows 原生组件），
> 后 Docker Desktop 装机成功（用户级安装 + WSL2 Ubuntu-24.04），**选型全面恢复容器形态**。
> Docker Hub 直连受阻，镜像统一经加速前缀 `${DOCKER_MIRROR:-docker.m.daocloud.io}` 拉取（备选 1ms 等源）。

### 2.1 前置条件

| 组件 | 说明 |
| :--- | :--- |
| Docker Desktop | 用户级安装（%LOCALAPPDATA%\Programs\DockerDesktop），WSL2 后端（Ubuntu-24.04） |
| Compose | v5.5.0+（`docker compose version` 验证） |
| 镜像加速 | 拉取失败按约定停下报告，可换 `DOCKER_MIRROR` 源重试，不盲目重试 |

### 2.2 十容器栈（`hercules-platform/deploy/docker-compose.yml`）

| 容器 | 镜像 | 端口 | 说明 |
| :--- | :--- | :--- | :--- |
| hercules-mysql | mysql:8.0 | —（容器网络内 3306） | `binlog-format=ROW` + `binlog-row-image=FULL` + `log-bin`（阶段 B 前置）；init 脚本建 canal 账号（存量卷需手动执行一次）；数据卷 `mysql-data` |
| hercules-redis | redis:7-alpine | —（容器网络内 6379） | L2 分布式缓存；熔断/回源锁演练对象 |
| hercules-rocketmq-namesrv | rocketmq:4.9.4 | —（9876 容器网络内） | NameServer；JVM 显式压小（镜像默认 8g 不可接受） |
| hercules-rocketmq-broker | rocketmq:4.9.4 | —（10911 容器网络内） | 挂载 `deploy/rocketmq/broker.conf`（autoCreateTopicEnable、ASYNC_FLUSH、brokerIP1=服务名） |
| hercules-canal | canal/canal-server:v1.1.7 | —（11111 容器网络内） | MQ 模式直投 RocketMQ：`canal.serverMode=rocketmq` + `canal.mq.*` 环境变量（flatMessage、topic、partitionHash=`.*\\..*$pk$`、**partitionsNum=8 必配**）；过滤 `hercules\.t_course`；账号 canal/canal（mysql_native_password） |
| hercules-app | hercules-app:dev（本地构建） | 8080 | 业务应用；`HERCULES_SYNC_TRANSPORT=canal-mq`（消费 binlog 链路刷缓存）；日志卷 `hercules-app-logs` |
| hercules-gateway | hercules-gateway:dev（本地构建） | **8081（压测入口）** / 8082（网关管理） | 路由 `/api/** → app:8080`，JWT 鉴权，traceId 生成；日志卷 `hercules-gateway-logs` |
| hercules-prometheus | prom/prometheus | 9090 | 抓取 app/gateway 的 `/actuator/prometheus` |
| hercules-grafana | grafana/grafana | 3000 | admin/admin123（演示口令）；自动装配 Prometheus 数据源 + Hercules 总览看板 |
| hercules-ui | hercules-ui:dev（宿主 `npm run build` 后构建） | **8090（浏览器入口）** | nginx 托管 dist + `/api` 反代网关（proxy_buffering off 保 SSE 流式）；阶段 G |

阶段 B 同步链要点：canal 账号需 `REPLICATION SLAVE/CLIENT + SELECT` 且以 `mysql_native_password` 认证
（canal 1.1.7 自研解析驱动不支持 MySQL 8 默认的 caching_sha2_password，实测 1045 拒绝）；
topic `hercules-binlog-topic` 建议手动预建 8 队列（`mqadmin updateTopic`）。

压测环境变量（app 容器）：`HERCULES_AUTH_DEMO_STUDENT_COUNT=60`（演示账号池 st001~st060）、
`HERCULES_LOADTEST_SEED=true`、`HERCULES_LOADTEST_COURSE_COUNT=5000`（启动时幂等播种压测课程，
`course_code LIKE 'LOADTEST-%'`，容量 100000/门，供压测写入不触发 409）。

### 2.4 压测（阶段 H-4，详见 `hercules-platform/loadtest/`）

```powershell
cd hercules-platform\loadtest
.\run-loadtest.ps1 -Threads 20  -Rampup 10 -Duration 60    # 冒烟
.\run-loadtest.ps1 -Threads 500 -Rampup 30 -Duration 600   # 500 并发稳态
```

- 脚本负责：登录取 token → 查压测课程 ID 区间 → 按 7:3 划分线程组 → 全参数写入属性文件 →
  JMeter 无头运行 + 看门狗限时 → 自动生成 HTML 报告（`reports/<时间戳>/index.html`）；
- JMX（`src/test/jmeter/hercules-loadtest.jmx`）为**双线程组**结构（读 70% / 写 30%），
  计划内无脚本元素与冷门控制器，认证头读取全局属性 `Bearer ${__P(token)}`。

### 2.6 与模式一的关系

- 模式一（本机 MySQL/Redis + 单进程）是**开发基线**：改代码后快速起进程自测，不依赖镜像重建；
- 模式二是**集成与压测标准形态**：网关、观测栈、后续中间件组件只在容器栈中演进；
- 两模式共用同一套 `schema.sql`/初始化逻辑与 `hercules.*` 业务参数，配置差异全部经环境变量注入。

### 2.7 论文口径（选型变更记录）

中间件选型经历「容器 → 原生/嵌入式（装机受阻期）→ 容器（恢复）」两次回调，
最终论文口径：**网关、观测、消息、检索等分布式组件一律容器化**（贴近真实部署形态），
嵌入式方案仅作为"受限环境下可运行"的对比项在论文中记录取舍过程。
