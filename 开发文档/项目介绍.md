项目介绍（简历用 · 纯文本版）
================================

高并发综合校园服务平台（个人项目）
GitHub：https://github.com/ZhanJHE/hercules-platform
技术栈：Java 21 · Spring Boot 3 · MyBatis-Plus · Caffeine+Redis 多级缓存 · 向量时钟 · Docker Compose
项目描述：面向高并发选课场景的服务平台，核心解决缓存击穿与分布式数据一致性问题。
个人贡献：
• 设计两级缓存架构（Caffeine+Redis），SingleFlight 合并回源 + 分布式回源锁防击穿，Resilience4j 熔断降级，Redis 故障时读路径 7ms 级快速恢复
• 引入向量时钟版本链 + 事务提交后事件同步 + 字段级 LWW 合并，保障多节点并发写最终一致
• 实现 JWT 双 Token 认证（AccessToken+RefreshToken）：旋转刷新、黑名单注销、认证审计落盘
• JMeter 500 并发阶梯压测：稳定 5000+ QPS、错误率 0.0007%；定位并修复 Hikari 连接池瓶颈（写 P95 -69%）

数字出处（面试防守参考）
================================
- 500 并发 = 500 线程（读 350 / 写 30%比例的线程组划分），稳态 10 分钟；
- 5,027 QPS / 错误率 0.0007%（20/3,018,549）：JMeter 阶梯压测 L3 实测，见《测试报告》§6.2；
- 7ms 级快速降级：Redis 故障演练中熔断 OPEN 后读路径延迟，见《测试报告》§三；
- 写路径 +86% / P95 -69%：Hikari 20→40 的 A/B 复跑对比，见《测试报告》§6.6；
- 面试可展开点：Hikari 瓶颈定位证据（waiting=116 日志）、向量时钟选型对比、单机压测口径分析（§6.5）、JMeter 冷门控制器缺陷排查。
